## 1. 運動神経系の位置づけ【LOCK】

「Godot＝運動神経」ではない。**Godot上に構築する身体制御エンジン**が、人体でいう運動神経系・運動制御に相当する。Godotはその実行・描画環境である。

- **Brain**：思考、知識、発話・作業の意味内容を決める。
- **Ghost**：Heart / Memory / Time / Relationship / Behavior に基づき、気分・感情・関係・自発行動・身体表現の意図を決める。Brainの事実・結論は書き換えない。
- **Character内の運動神経系（身体制御エンジン）**：Ghostからの表現意図を受け、骨格・表情・視線・呼吸・姿勢の具体的な時間変化へ変換する。
- **Characterの身体（VRM等の3Dモデル）**：ボーン、表情・メッシュ等が駆動され、実際の見た目として現れる。

流れ：**Brain → Ghost →（身体表現プロトコル）→ Character内の運動神経系 → 3D身体**。

この運動神経系を**第四の独立した柱としない**。Characterの内部機能として構築する。

## 2. 身体制御の責務【LOCK】

- Ghostが身体の関節角度を毎フレーム直接計算するのではなく、運動神経系が表現意図から連続的な動作へ変換する。
- 瞬き・呼吸・微小な重心移動・自然な待機姿勢などはGhost通信が途切れてもCharacter側で維持できる構造とする。
- 同じ表現意図でも、状況や時間に応じて単純反復にならない自然な変化を許容する。
- 動作のブレンド、可動範囲、身体の破綻防止は運動神経系が担う。
- Ghostの感情・関係性・自発性を運動神経系が勝手に改変しない。運動神経系は受け取った意図を身体表現に変換する。
- LOCK済みの舞台スタッフ少女の見た目・衣装・装備は変更しない。

## 3. プロセスとアプリ化の原則【設計方針・未実装】

**利用者から見れば一つのロボットアプリ**を目指す。ただし、内部はBrain・Ghost・Characterを独立した責務・プロセスとして維持しうる。

- Brain＝Python、Ghost＝Python、Character＝Godot、接続＝ローカルWebSocketという第一技術構成LOCKを維持する。
- Godotプロジェクトは将来、運動神経系と3D身体を含む独立実行アプリとして書き出す想定。
- **統合ランチャー／起動監督**が一度の起動で各コンポーネントを起動・監視・停止する構想とする。
- Ghost停止時にもCharacterの最低限の待機動作が継続し、接続復旧時に再同期できることを目標とする。
- ランチャー方式、OSの自動起動／ログイン常駐、プロセス再起動方式、通信メッセージ形式、アプリのパッケージ方式は**未決定**。今ここで特定のOSや単一プロセス構成をLOCKしない。
