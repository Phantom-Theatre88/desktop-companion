# LOCK 52｜CoreS3単体DeskRobo先行

更新日: 2026-09-17

## 決定

外付け感覚器官を増設する前に、**M5Stack CoreS3単体でDesktop Companionを「DeskRoboとして生きている状態」まで成立させる**。

最上位ゴールはセンサー数を増やすことではなく、

**「机の上に常にいて、周囲を感じ、反応し、気分が変わり、少しずつ関係性が育つ相棒」**

を成立させることである。

そのため、Step 4完了後に直ちにToF4M / U172へ進む旧順序を上書きし、まずCoreS3単体DeskRoboを成立させる。

## CoreS3単体DeskRoboの最低成立条件

外付けUnitやPi5が無くても、少なくとも以下が常時成立すること。

1. Ghost（Heart / Memory / Time / Relationship / Behavior）が起動時から常駐する。
2. HeartとTimeがBehaviorへつながり、待機中にも生命感のあるMicroBehaviorを生成する。
3. Face / Eyeは固定画像の切替ではなく、視線・開眼度・瞬き・左右差等を連続量として受け取れる。
4. 何も入力がない時も、完全静止のテスト画面ではなく「そこにいる」待機状態を持つ。
5. CoreS3本体だけで利用可能な感覚（Touch / IMU等）は、外付けUnitより先にDeskRoboの反応へ接続する。
6. Heart状態が身体表現へ反映できる本番経路を持つ。
7. Pi5や外付けセンサーが無くても基本生命活動を継続する。

## 実装順の変更

Step 4の次は、以下を優先する。

**Ghost / Heart / Time → Behavior / MicroBehavior → Face / Body → CoreS3内蔵感覚 → 単体DeskRobo成立**

その後に最初の外部感覚としてToF4M / U172を追加する。

ToF4Mが最初の「外部感覚縦貫通対象」であるLOCKは維持する。ただし、**外部感覚縦貫通の開始条件を「CoreS3単体DeskRobo成立後」へ変更する。**

## 実装上の注意

- 後で捨てるデモ用生命感コードは作らない。
- MicroBehaviorはGhost / Behavior配下の本番経路として実装する。
- 単純ランダム動作だけで人格を表現しない。
- 表情はプリセット切替を完成形としない。
- 数値・周期・振幅等の初期実装値は調整可能な実装パラメータとし、人格LOCKとして固定しない。
- 外付けセンサーの不具合を、単体DeskRobo完成のブロッカーにしない。

## 完成判定

机上にCoreS3単体を置いた状態で、会話や外付けセンサーが無くても、Heart・時間・身体表現・内蔵感覚によって、**「ただ表示している基板」ではなく「そこにいる相棒の最小形」**として観察できること。

このLOCKは、旧Step 5のToF4M先行順序に対して優先する。
