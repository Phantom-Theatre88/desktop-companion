## 1. 最上位ゴール【LOCK】

長期記憶を維持し、複数のプロジェクトを継続でき、情報保護を重視したAIを作る。
そのAIに、既存設計に基づくGhostという「心」と、LOCK済みの舞台スタッフ少女の3Dキャラクターという「身体」を与える。

最終的には、相談・研究・制作・検証を続けられるAIが、キャラクターとして常駐し、対話・表情・動作で振る舞う状態を目指す。
実装の可否や性能は、実際のテスト結果で判断する。推測を完成報告にしない。

## 2. 三本柱と責務境界【LOCK】

### ① Brain｜頭脳
- 考える：推論・知識・会話内容・研究・作業計画・作業実行。
- プロジェクトの長期記憶：聖典・LOCK・資料・進捗・実ファイル・変更履歴・引き継ぎ。
- ローカル統合Brainを中心に、必要なときだけ専門Brain（ローカルまたは外部）を活用する構想。
- 外部への情報流出を防ぐため、LLMの自己判断だけに依存しない送信制御を設ける。外部送信の許可条件・具体的方式は未実装・未確定。
- Kimとローカル側で、専門Brainの結果を根拠・LOCK・実ファイルと照合し、ズレを指摘・修正できる方向を維持する。これを第4の独立した柱にはしない。

### ② Ghost｜心と身体表現の制御
- Brainとは独立したシステム。LLMを「心」とみなさない。
- 既存LOCKの **Heart / Memory / Time / Relationship / Behavior** を継承する。
- 現在の気分・感情・経験・関係性・自発行動を扱い、声・口調・表情・仕草・身体動作の表現を決める。
- **Brainの事実や結論をGhostが勝手に変更しない。**
- GhostのMemoryはキャラクターの経験を扱い、Brainのプロジェクト長期記憶とは役割を混同しない。
- GhostからBrainへ発話や判断の要求を送ることはできる。

### ③ Character｜3Dキャラクター
- LOCK済みの舞台スタッフ少女の外観を正本とする。勝手に別人や別衣装にしない。
- 茶色のポニーテール、黒の8bit Lighting Theatreポロシャツ、黒のカーゴパンツ、腰のトランシーバー・作業装備等を忠実に再現する。
- 3Dモデルとして360°整合し、全身ボーン・表情・視線・まばたき・口パク・動作を制御できるようにする。
- 一枚絵を揺らした動画や、モデル化できない設定画を「3D完成」と扱わない。

### 三者の連携
**Brain が何を伝えるかを考える → Ghost が現在の気分と関係性を踏まえて伝え方・振る舞いを決める → Character が声・表情・動作として表現する。**

## 3. 実装の基本方針【LOCK】

- 三本柱は**並行開発**し、各柱の単体完成を待たずに小さく統合して検証する。
- 最初に既存資産とLOCKを照合する。既に確定したGhostの設計をゼロから再検討しない。
- 接続仕様（Brain→Ghost、Ghost→Character、Ghost→Brain）を早期に定義し、責務境界を崩さない。
- 全ての作業で「仕様と事実の確認 → 実装 → 検証 → 記録」を行い、未完成は未完成と明記する。
- ハードウェア選定は要求能力と実装検証の結果に基づいて行う。ミニPCや特定LLMの機種を現段階で確定しない。

## 4. 三本柱ごとの最初の完成条件【開発目標】

### Brain
- セッションを終了しても前回のLOCK・聖典・作業進捗を正しく参照できる。
- 翌日も実ファイルと照合して、同じプロジェクトの続きを行える。
- 作業結果を検証し、履歴と次の作業へ引き継げる。
- 情報の外部送信が許可条件に従って制御される。

### Ghost
- 既存の五中核を確認し、実装資産を再利用できる範囲を検証する。
- Brainから受け取った意味内容を変えずに、表情・口調・動作の指示に変換できる。
- 時間・出来事・関係性による状態変化と自発行動を検証する。

### Character
- LOCK原画と顔・髪・衣装・装備の一致を確認できる3Dモデルを作る。
- 骨格による首・腕・胴体等の動作と、表情・口パク・視線を外部指示で制御できる。
- 静止画や事前レンダリング動画でなく、操作可能なモデルデータを成果物とする。

## 5. 実装順序【基本ロードマップ】

1. **既存資産の棚卸し**：Brain関連資産、Ghostの既存実装・聖典、Characterの正本画像と制作状況を確認する。
2. **接続仕様の定義**：BrainとGhost、GhostとCharacterの入出力・責務境界・エラー時動作を決める。
3. **三本柱の単体試作**：Brain＝記憶と作業継続、Ghost＝状態変化と表現指示、Character＝3D骨格・表情制御を個別に動かす。
4. **最小統合**：Brainの発話内容→Ghostの表現判断→Characterの発話・動作を一連で実証する。
5. **総合検証**：日をまたぐプロジェクト継続、LOCK参照、成果物検証、外部通信の安全性、Ghostの状態と表現の整合性を確認する。

各工程は実装状況・テスト結果に基づき改善してよい。ただし第1〜3節のLOCK事項を黙って変更しない。
