# AKARI Character 制作・実装改善指示書

## 1. 最上位目的

Ghostが自らの意思、感情、記憶、時間、関係性に基づいて行動し、その内面をAKARIの身体を通じて自然に表現できる、生命感のあるAIキャラクターを完成させる。

完成品質の参考は以下とする。

- **CODE27**：存在感、自発性、自然な振る舞い、生活感。
- **Live2D**：イラストの可愛らしさを維持した自然な動作・表情表現。
- **AKARI**：承認済みキャラクターデザインと独自のGhostによる人格・行動。

CODE27やLive2Dを模倣すること自体を目的とせず、それらの優れた技術と表現品質を参考にする。

## 2. 現在の小ゴール【正式LOCK継承】

**骨格制御＋描き分け＋パーツ合成による、リアルタイムの2Dアニメーションシステムの完成。**

この三要素が独立して存在するだけではなく、一体として機能し、外部から与えられた身体表現の指令に応じて、AKARIが自然に動くCharacterシステムを完成させる。

最終3D身体の並行開発方針は変更しない。

## 3. これまでの制作方法の問題

- 独自のボーン制御に依存しすぎていた。
- 3Dの骨格制御を2D画像にそのまま適用していた。
- 82基本パーツを用意したが、十分に活用できていない。
- 描き分け素材間で身体比率や造形が統一されていない。
- 個別の不具合修正に集中し、システム全体の完成を見失っていた。
- 既存の優れたアニメーション技術を調査しても、実際の導入・比較検証に至っていない。
- 静止画像による評価が中心となり、連続動作の品質検証が不足していた。

今後はこの制作方法を繰り返さない。

## 4. 制作方法の変更

| 従来の方法 | 今後の方法 |
|---|---|
| 独自ボーン制御の開発 | 実績のある2D制御技術の活用 |
| パーツ単位の局所修正 | Character全体の品質改善 |
| 画像の回転・変形中心 | 骨格・描き分け・合成の統合 |
| 素材ごとに独立した制作 | 共通身体寸法・造形基準による制作 |
| 静止ポーズでの評価 | リアルタイム連続動作での評価 |
| 不具合ごとの場当たり的修正 | 根本原因を特定したシステム改善 |
| 実装した項目数による進捗評価 | 完成条件を満たした機能による評価 |

## 5. 既存技術の積極的な活用

以下の技術を実際のサンプル、ソースコード、動作環境を用いて検証する。

### Live2D

- パラメーターによる身体表現
- デフォーマーとメッシュ制御
- 表情・視線・瞬き・呼吸
- 方向別の描き分けと変形
- 物理演算による髪や衣装の動き

### Spine

- 人体骨格リグ
- IK・関節制約
- メッシュウェイト
- Attachmentによる素材切替
- 動的な描画順
- アニメーション間のブレンド

### Godot

- Skeleton2D・Bone2D
- IKとメッシュ制御
- リアルタイムパーツ合成
- アニメーションブレンド
- 外部プログラムからの身体制御
- NERVAとの接続

既存技術で実現できる機能は積極的に活用し、同等の機能を理由なく独自開発しない。

調査のみで終了せず、実際に動作するサンプルで品質、制御性、ライセンス、費用、実行環境との適合性を比較する。

Godotを第一実装候補とする既存LOCKは維持し、正式な採用変更が必要な場合のみ承認を求める。

## 6. Characterシステムの構成

### A. 骨格制御

人体として自然な関節、可動範囲、骨格間の連動を実現する。

### B. 描き分け制御

姿勢、関節角度、身体の向き、表情に応じた素材を選択する。

描かれていない面を無理な画像変形で補わない。

### C. パーツ合成

82基本パーツ、衣装、装備、方向別素材、補完素材を適切に合成する。

身体比率、輪郭、関節接続、重なり、描画順を維持する。

### D. 動作統合制御

複数の動作を同時に表現し、動作間を自然に遷移させる。

呼吸、瞬き、視線、表情、姿勢、手足の動作、髪や衣装の追従を組み合わせられる構造とする。

### E. 外部制御インターフェース

NERVAからの身体表現指令を受け取り、Characterの動作へ変換する。

動作の実行結果、完了、失敗、制御不能状態を返却できる構造とする。

既存のBrain・Ghost・Character・NERVAの責務は変更しない。

## 7. 制作素材の管理

合格済みのAKARIの直立姿勢を造形基準とする。

- キャラクターデザインを勝手に変更しない。
- 身体寸法、肉付き、顔、手足、衣装の一貫性を維持する。
- 82基本パーツの実用性を監査し、必要な箇所に接続する。
- 不足する方向別・関節補完素材を制作する。
- 素材数を増やすこと自体を目的としない。
- 合格済みの素材と実装を保全する。

数値上の寸法一致だけでは合格とせず、人体として自然に見えることを確認する。

## 8. 実行工程

### STEP 1｜既存システムの実動作検証

Live2D・Spine・Godotの実装サンプルを確認し、AKARIに利用可能な機能を特定する。

独自開発が必要な部分と既存技術を利用する部分を切り分ける。

### STEP 2｜Character基盤の統合

既存AKARI素材を利用し、骨格制御・描き分け・パーツ合成を一体化する。

腕上げを最初の統合検証に使用する。ただし、腕上げの完成を小ゴールに置き換えない。

### STEP 3｜全身のリアルタイム表現

- 呼吸・瞬き
- 視線・表情
- 首・肩・上半身の動作
- 手・腕・指の動作
- 下半身・姿勢の変化
- 振り向き・方向転換
- 動作間の滑らかな遷移

これらを同一Characterシステム上で制御できる状態にする。

### STEP 4｜生命感の品質検証

複数の動作を組み合わせ、キャラクターが自然に存在しているように見えるかを検証する。

静止画だけでなく、実際のリアルタイム動作で確認する。

### STEP 5｜NERVA・Ghostとの接続検証

Ghostの意味的な行動意図が、NERVAを通じて自然な身体表現に変換されることを確認する。

固定アニメーション番号の再生だけに依存せず、動作・表情・視線・姿勢を状況に応じて組み合わせられることを検証する。
