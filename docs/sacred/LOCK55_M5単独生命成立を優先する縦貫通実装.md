# LOCK 55｜M5単独生命成立を優先する縦貫通実装

更新日: 2026-09-19

## 決定

Desktop Companionの次工程は、外部感覚器官を横方向に増やすことを優先しない。

最上位ゴールである、

**「机の上に常にいて、周囲を感じ、反応し、気分が変わり、少しずつ関係性が育つ相棒」**

および、

**「そこにいる感じ」**

を先に成立させるため、現在すでに実機で通っている感覚経路を使い、

**Camera / Touch / IMU → Semantic Neuron → Ghost → Heart → Behavior → Face / Neck**

を縦方向に生命として完成させる。

## 現在地

実機では以下が成立済み。

- CoreS3単体生命ループ
- Face / MicroBehavior
- Touch
- IMU
- Camera
- Vision
- `MOTION_DETECTED / BRIGHTER / DARKER`
- Vision → Semantic Neuron → Ghost / Heart / Memory / Behavior の実機縦貫通
- Camera使用後の内部I2C復元
- VisionとIMUの共存

一方で、以下は未成立。

- Heart数値がイベントや時間で実際に変化すること
- TimeEngineによる生活時間・経過時間の意味化
- RelationshipEngineによる関係性変化
- Ghost状態からの自発的Behavior選択
- 内蔵2軸首サーボを含む身体出力
- M5Stackちゃん単独で「そこにいる感じ」が成立すること

## 次の優先順

### 1. Heartを実際に動かす

現在の `HeartEngine` は本番骨格・永続化・復元方針まで存在するが、
Semantic Neuronを受けても `mood / affection / curiosity / boredom / sleepiness / attention`
の実値変化は未実装である。

次はまず、

- TOUCH
- PICKED_UP
- SHAKE
- MOTION_DETECTED
- BRIGHTER
- DARKER
- 無刺激時間

等を、既存LOCK 18〜35に従ってHeart変化へ接続する。

具体係数・閾値は、実装上必要な最小限だけ決め、実機観察で調整する。

### 2. Behaviorを「自発行動」へ進める

Heart / Time / Memory / 現在感覚を材料に、

- 視線
- 瞬き
- Face
- 内蔵2軸首
- 小さな身体表現
- 何もしない

から理由のある行動を選択できる状態へ進める。

単純ランダム動作ではなく、Ghost状態を根拠にする。

### 3. M5Stackちゃん単独生命を成立させる

Pi5が存在しなくても、

- 周囲の変化に気づく
- 触られたことを感じる
- 持ち上げられたことを感じる
- 気分が少し変わる
- 時間経過で状態が変わる
- 自分から小さく行動する
- 何もしない時間も生命感がある

状態を成立させる。

これを外部感覚追加より優先する。

### 4. 外部感覚を追加する

M5単独生命が成立した後、

- ToF4M
- TMOS PIR
- ENV-Pro
- 聴覚
- その他感覚

を追加する。

ToF4Mは引き続き**最初の外部感覚**であることを維持する。

ただし、最初の外部感覚であることと、現在の次工程であることは同義ではない。

## LOCK 54との関係

LOCK 54の、

**A「感じる」→ B「気分が変わる」→ C「自分から行動する」→ D「昨日と今日をつなぐ」→ E「賢くする」**

という大工程は維持する。

ただしAを「すべての感覚器官を先に実装し終える工程」と解釈しない。

現在実装済みの感覚を使って、

**感じる → 気分が変わる → 自分から行動する**

を一本の縦貫通として先に成立させる。

その後、ToF4M等の感覚器官を追加し、同じ縦貫通構造へ接続する。

## 判断原則

今後の実装判断は常に、

**最終ゴール → 全体構造 → 現在の小ゴール**

の順で行う。

センサー数や機能数を増やすこと自体を進捗とは見なさない。

**M5Stackちゃん単独で「そこにいる感じ」が増えたか**を優先評価する。
