# LOCK 37｜後回しイベントは処理時点で有効性を再評価し、意味を失ったものは破棄できる

更新日: 2026-09-17

## 決定
複数イベントが競合して低優先度イベントが後回しになった場合、そのイベントを必ず無条件に実行するのではなく、**実際に処理する時点で、そのイベントがまだ現在状況に対して意味を持っているかを再評価する**。

処理時点ですでに意味を失っているイベントは、Heart更新や身体反応へ通さず、破棄できる構造とする。

## 理由
イベントが発生した瞬間には妥当だった反応でも、優先度競合によって処理が遅れた結果、外界の状況がすでに変わっている場合がある。

たとえば、

- 「人が近づいた」というイベントが発生する
- 同時に、より重要度の高い安全イベントや強い対人イベントが発生する
- 「人が近づいた」が後回しになる
- その間に相手がすでに離れる

という状況で、後から古い「人が近づいた」イベントに従って視線・首・表情などを動かすと、現実世界と反応の時間軸がずれ、不自然な挙動になる。

したがって、**イベントを受け取った事実を保持すること**と、**そのイベントに対して今この瞬間に身体反応やHeart更新を実行すること**は分けて扱う。

## 基本原則
- 高優先度イベントを先に処理する方針はLOCK 36を維持する
- 低優先度イベントは即座に捨てず、後段へ回せる
- ただし、後段で処理する際に現在状況との整合性を確認する
- 現在状況に対して意味を失ったイベントは、反応実行対象から外してよい
- 「一度キューへ入ったから必ず最後まで処理する」という構造にはしない
- 破棄対象になったイベントを、Memory上の履歴として残すかどうかは別問題とし、現段階では固定しない

## 重要な境界
このLOCKで決めるのは、**遅延イベントの有効性を処理時点で再評価できること**だけである。

現段階では以下を固定しない。

- 何秒経過したら古いと判定するか
- イベント種別ごとの有効期限
- 再評価に使う具体的なSensor / Semantic Neuron条件
- TTLやタイムアウト値
- Memoryへ履歴保存する条件
- 破棄イベントを学習材料へ使うかどうか

これらは実装・実機挙動を見ながら決める。

## ゴールとの関係
本LOCKの目的はイベント処理を機械的に消化することではなく、**現在の世界に対して自然なタイミングで反応する相棒にすること**である。

「出来事を忘れないこと」と「もう終わった刺激へ遅れて身体反応すること」は同一ではない。

最上位ゴールである、

**「机の上に常にいて、周囲を感じ、反応し、気分が変わり、少しずつ関係性が育つ相棒」**

および評価基準である **「そこにいる感じ」** を優先し、過去のキューを消化するためだけの不自然な反応は避ける。
