# LOCK 35｜1イベント処理中は開始時のHeart Contextスナップショットを固定して使う

更新日: 2026-09-17

Heart Contextは常に最新値を参照し続けるのではなく、**1つのイベント処理を開始した時点で読み取り専用スナップショットを取得し、そのイベント処理が完了するまでは同じHeart Contextを使う**構造とする。

## 基本方針

- Semantic Neuronから1つのイベント処理を開始する時点で、その瞬間のHeart Contextを取得する
- 取得したHeart Contextは、そのイベントに対するSynapseの通り方・反応強度・Behavior Selectorでの判断が完了するまで固定する
- イベント処理の途中でHeart Engine内部の `mood / affection / curiosity / boredom / sleepiness / attention` 等が更新されても、処理中のイベントが参照しているHeart Contextへ後から反映しない
- 次に開始されるイベント処理では、その時点の最新Heart状態から新しいHeart Contextスナップショットを取得する
- Heart ContextそのものはLOCK 34に従い読み取り専用とし、SynapseやBehavior側から書き換えない

## 理由

1つの反応を処理している途中でHeart状態が変化するたびに参照値まで入れ替わると、同じイベントの途中で判断基準が変わり、Synapseの判断・反応強度・Behavior選択が揺れる可能性がある。

そのため、**「1回の反応は、その反応を始めた瞬間の内面状態を基準に最後まで処理する」**ことを基本とする。

たとえば、人が近づいたイベントを処理し始めた時点で `affection` が高く `mood` が低かった場合、そのイベントに対する反応はその状態を基準に決める。処理途中で別イベントによって `mood` が上昇しても、すでに進行中の「人が近づいた」イベントの判断を途中から別のHeart Contextへ切り替えない。

一方、次に発生するイベントは更新後のHeart状態から新しいスナップショットを取得するため、Ghost全体としてはHeart変化が次の反応へ自然に反映される。

## 責任分離

- **Heart Engine**：Heart内部状態を更新し、現在状態からHeart Contextスナップショットを生成する
- **Heart Context**：イベント開始時点の内面状態を保持する読み取り専用データ
- **Synapse**：そのイベントに紐づく固定Heart Contextを参照して、入力の通り方・条件・反応性を修飾する
- **Behavior Selector**：同じイベントに紐づく固定Heart Contextと、外界状況・対人Session・安全優先度・身体資源競合等を合わせて身体表現を選ぶ
- **Body**：選ばれた表現を実行する

## 境界

このLOCKでは、イベント処理開始時にHeart Contextを固定するという骨格だけを決める。

以下は現段階では固定しない。

- スナップショットを生成する具体的な関数・クラス設計
- イベント処理の厳密な開始・終了判定
- 複数イベントが同時進行した場合のキュー方式・並列方式
- スナップショットの保持時間
- Heart Contextの更新周期
- 各Heart項目の係数・閾値

これらは実装時に必要になった段階で決める。

このLOCKはLOCK 33・LOCK 34を補足し、上書きしない。
