# LOCK 51｜Heart永続化保存方式

更新日: 2026-09-17

## 決定

Heartの永続化は、**NVS主保存＋microSDバックアップ**の二重化構成とする。

### 主保存

CoreS3内部のNVSを主保存先とする。

- Arduino環境では `Preferences` を使用する
- 通常起動時はNVSを第一の復元元とする
- 電源断・再起動後もHeart状態を引き継げることを目的とする
- Heartのような少量かつ起動時に必ず必要な状態を、外部メディアの有無に依存させない

### バックアップ

microSDをバックアップ先とする。

- NVSとは独立した復旧用コピーを保持できる構造にする
- 人間が取り出して確認・複製・保全できる形を前提とする
- 将来のMemory・履歴・ログ等の外部保存と接続可能な境界を持たせる
- microSD未挿入・マウント失敗時でも、M5Stack側の基本生命活動とNVSからのHeart復元は継続できる

## 復元原則

既存LOCK 19・20を維持する。

- 初回起動または明示的初期化時のみ基準初期値を使用する
- 通常起動では保存済みHeart状態を使う
- `affection`、`mood`、`curiosity`、`boredom`、`sleepiness`、`attention` は同一方法で機械的に復元せず、各LOCKに従って復元する
- センサーキャリブレーションとHeart保存値は分離する

## 障害時の考え方

- NVSが正常ならNVSを主として使用する
- microSDはNVSの代替常用ストレージではなく、バックアップ・復旧経路とする
- microSD障害だけで起動不能にしない
- NVS側の保存異常・破損時にmicroSDバックアップから復旧できる構造を目指す
- 具体的なバックアップ周期、世代数、ファイル形式、破損判定、復旧優先順位は、実装上必要になるまで先行固定しない

## 実装原則

このLOCKで固定するのは**保存先の役割分担**までとする。

固定する：

- NVS = 主保存
- microSD = バックアップ
- Heart永続化は二重化する
- microSDがなくても基本起動可能にする

まだ固定しない：

- 保存周期
- バックアップ世代数
- microSD上のファイル形式
- チェックサム等の破損判定方式
- 復旧時の細かな優先順位
- 書込み回数最適化の具体値

これらは実装・実機確認で必要になった時点で決める。
