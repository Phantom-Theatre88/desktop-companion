# LOCK 36｜複数イベントは重要度の高いものから先に処理し、低優先イベントは捨てない

更新日: 2026-09-17

Heart / Synapse / Behavior 系へ複数のSemantic Neuronイベントがほぼ同時に到来した場合、単純な到着順だけで処理したり、同時期のイベントを無条件に1つへまとめたりせず、**重要度の高いイベントを先に処理し、残りは後続処理へ回す**構造とする。

## 基本方針

- 複数イベントが近接して到来した場合、重要度・優先度の高いイベントから先に処理する
- 安全に関わる反射、強い対人イベントなど、即時性の高いものは優先して通す
- 優先度の低いイベントは、単に捨てるのではなく、後続処理へ回せるように保持する
- 「優先する」と「他を無視する」は分けて扱う
- イベントが多い状況でも、Ghostが重要な刺激へ先に反応しつつ、周囲の出来事そのものを無かったことにしない構造を目指す

## 既存LOCKとの関係

- 行動優先順位の上位にある安全・強い反射を最優先する既存方針を維持する
- 対人Session中の意味のある関わりは高い優先度を持ち得る
- Heart ContextはLOCK34〜35に従い、各イベント処理開始時点の読み取り専用スナップショットを基準にする
- 先行イベントの処理によってHeart状態が変化した場合、後続イベントは自分の処理開始時点で新しいHeart Contextスナップショットを取得する

## 現段階で固定しないもの

以下は実装骨格ではなく調整領域なので、まだ固定しない。

- 優先度の具体的な数値
- キュー長
- タイムアウト
- 同時到来とみなす時間幅
- イベント破棄条件
- 重複イベントの圧縮方式
- 緊急イベントによる割り込み実装の詳細

まずは、**「重要なイベントを先に通す。ただし、低優先イベントを捨てず後で処理できる」**という骨格のみをLOCKする。
