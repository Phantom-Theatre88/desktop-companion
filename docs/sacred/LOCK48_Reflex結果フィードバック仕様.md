# LOCK 48｜Reflex後のHeart更新は反射の成否・危険継続状態まで受け取る

更新日: 2026-09-17

Reflexが発火した場合、Heartへ返す情報は「反射が起きた」という事実だけに限定しない。

Reflex実行後には、少なくとも以下のような結果情報をHeart側へ返せる構造とする。

- 回避・防御・停止などの反射行動が実際に成立したか
- 危険刺激が消えたか、まだ継続しているか
- 身体側が安全状態へ戻れたか
- 反射後も注意・警戒を維持すべき状態か

これにより、同じ「びっくりして反射した」という出来事でも、

- **びっくりしたが、すぐに危険が去った**
- **びっくりし、回避できず、危険が続いている**

を同じHeart変化として扱わない。

基本構造は、

**刺激 → Semantic Neuron / Synapse → Reflex → 身体反応 → Reflex結果 → Heart更新**

とする。

Reflexは安全・強い反射としてHeartより先に身体を動かせるが、その後のHeartは、身体がどう反応したか、その反応が成功したか、現在も危険が残っているかという結果を受け取って現在状態を更新できる。

たとえば、

- 回避に成功し危険が消えた場合は、`attention` は一時的に高まっても、その後は安心方向へ戻りやすい
- 危険が継続している場合は、`attention` や警戒方向の内面状態を維持しやすい
- 同じ種類の失敗や危険継続が繰り返される場合は、Memory / Relationship / 長期傾向の材料にもなり得る

ただし現段階では、Reflex結果をどのHeart項目へ何点反映するか、具体的な変化量、閾値、タイムアウト、成否判定ロジックまでは固定しない。

まずは、**Reflexの結果と現在の危険継続状態をHeartへフィードバックできること**を実装骨格としてLOCKする。
