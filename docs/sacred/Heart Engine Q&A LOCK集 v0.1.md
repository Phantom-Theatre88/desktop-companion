# Heart Engine Q&A LOCK集 v0.1

更新日: 2026-09-17

この文書は、Heart Engineに関するQ&Aで正式LOCKした内容を、実装時に参照しやすいよう集約した聖典である。

## LOCK 18｜Heart Engine数値表現
- 内部値は `0.0〜1.0` を正本とする
- 表示・デバッグ値は `0〜100`
- イベント1回あたりの変化量は原則 `-0.1〜+0.1`
- 計算後は必ず `0.0〜1.0` に収める

## LOCK 19｜Heart Engine起動・永続化
- 初回起動または明示的初期化時のみ項目ごとの基準初期値を使う
- 通常起動では保存済みHeart状態から再開する
- センサーキャリブレーションとHeart初期化は分離する

## LOCK 20｜Heart再起動時の状態復元
- `affection` は長期関係状態として永続する
- `mood / curiosity` は前回値を参照しつつ平常値方向へ減衰して復元する
- `boredom` は停止時間・現在状況から再計算する
- `sleepiness` は現在時刻・生活リズムから再計算する
- `attention` は一時状態として平常値方向へ戻す
- 一時感情は電源断時の状態をそのまま凍結保存しない

## LOCK 21｜Heart平常値の長期変化
- 平常値は固定定数にしない
- 長期経験・関係性・生活履歴により少しずつ変化する
- 一時状態の減衰先は、その時点の動的な平常値とする
- 平常値はGhostの長期的な性格・傾向の一部とする

## LOCK 22｜Heart平常値の変化速度
- 平常値は数日〜数週間単位でゆっくり変化する
- 単発イベントや数時間程度の出来事で人格傾向を大きく変えない
- 同種経験が蓄積して初めて平常値へ反映する

## LOCK 23｜Heart平常値の学習材料
平常値の長期変化には、単純なイベント回数だけでなく以下を使う。
- イベント種類・回数
- 継続時間
- 最近の傾向
- `affection` 等のRelationship / Heart状態
- 時間帯・曜日・よく一緒にいる時間
- 起動時間・不在時間・日々の反復傾向

生活パターンは、単なる時計条件ではなく「どのような時間を一緒に過ごしてきたか」という経験の一部として扱う。

## LOCK 24｜Heart平常値は良化・悪化の両方向へ変化する
- 良い経験が積み重なれば良い方向へ変化する
- 長期不在、嫌がる刺激、生活リズムの乱れ等が続けば悪い方向へも変化する
- 単発イベントで壊れる構造にはしない

## LOCK 25｜Heartの回復性
- 悪化したHeartは時間経過だけでもゆっくり自然回復する
- 良い経験や安心できる関わりがあると回復が速まる
- 自然回復だけで過去の経験を即座に帳消しにしない
- 永久に悪化状態へ固定される構造にはしない

## LOCK 26｜Heart回復先は動的な平常値
- 回復先は固定された初期値や共通中立値ではない
- Relationship・長期履歴を反映した、その時点の動的な平常値へ戻る
- 同じ出来事から回復しても、関係性や育ち方により「戻る場所」は異なる

## LOCK 27｜Heart初回起動時の基礎人格
完全初回起動時は、
**少し好奇心が高く、少し人懐っこい基礎人格**
から開始する。

## LOCK 28｜Heart初回起動時の具体値
初回起動時は、少し元気で、人懐っこく、好奇心はやや高いが落ち着きは保つ。
- `mood = 0.60`
- `affection = 0.55`
- `curiosity = 0.65`
- `boredom = 0.15`
- `sleepiness = 0.15`
- `attention = 0.50`

見え方：
**「初対面でも人を嫌っていない。好奇心が強めで、周囲をよく見る。少しだけ元気で、反応も一拍早い。ただし落ち着きはある。」**

## LOCK 29｜Heartイベント強度は3段階
Semantic NeuronからHeart現在値へ影響するイベントは、基本強度を
**弱・中・強**
の3段階で扱う。
- 弱：小さな刺激・軽い関わり
- 中：はっきり認識できる通常の出来事
- 強：強い刺激・重要な出来事
- 同じイベントでも継続時間・文脈・Relationship・直前状態などにより段階は変わり得る

## LOCK 30｜Heartイベント強度は3段階分類＋連続可変値
- `弱 / 中 / 強` は固定数値そのものではなく、人間が理解しやすい分類ラベルとする
- 実際の内部変化量は各段階の中で連続可変値として扱う
- 同じ弱・中・強でも毎回同じ変化量にはしない
- 実変化量はイベント内容・継続時間・現在のHeart状態・Relationship・直近履歴・文脈等を組み合わせて算出する
- `強+` のように段階を増やすより、3段階のまま内部値を滑らかに変化させる
- 内部変化量はLOCK 18の原則 `-0.1〜+0.1` を基本とする

概念上は、
`基礎強度 × 継続時間係数 × Relationship係数 × Heart状態係数 × 履歴・文脈係数`
のような構造で最終変化量を求める。

ただし、この式そのものを固定LOCKするものではない。

## LOCK 31｜Heart可変強度を決める基本優先順位
同じ `弱 / 中 / 強` の中でも実際のHeart変化量は固定せず、基本的に以下の順で重く扱う。

1. **出来事そのものの内容**
2. **Relationship**
3. **その時のHeart状態**
4. **継続時間**

- まず「何が起きたか」を最重要とする
- 同じ出来事でも、相手とのRelationshipによって受け止め方は変わる
- さらに、その時の気分・注意・好奇心など現在のHeart状態によって反応量は変わる
- 継続時間は重要だが、出来事の意味や関係性を上書きする最上位要素にはしない
- この順位は絶対的な固定係数ではなく、Heart変化量を算出するときの基本優先原則とする

これにより、単なる時間の長さや固定数値ではなく、**「何が起き、誰との関係で、その子が今どう感じているか」**を中心にHeartが変化する構造とする。

## LOCK 32｜1イベントは主作用1つ＋副作用複数を持てる
Semantic NeuronからHeartへ入る1つのイベントは、Heartの1項目だけに限定して作用させず、**主作用1つと、副作用として複数のHeart項目へ同時に影響できる**構造とする。

- イベントには、その出来事の中心となる主作用を1つ持たせる
- 必要に応じて、他のHeart項目へ副作用を持たせてよい
- たとえば「撫でられた」なら、主作用は `affection` 上昇としつつ、`mood` や `attention` にも副作用を与えられる
- 主作用と副作用の具体的な変化量は、現段階では固定しない
- 副作用を無制限に増やすこと自体を目的にせず、そのイベントの意味として自然な範囲に限定する
- 実変化量はLOCK 29〜31の強度分類・連続可変・基本優先順位に従う

これにより、1つの出来事から複数の内面変化が自然に連動し、単純な「1イベント＝1数値更新」ではないGhostらしい反応を可能にする。
