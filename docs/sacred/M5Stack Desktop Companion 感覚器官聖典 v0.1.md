# M5Stack Desktop Companion 感覚器官聖典 v0.1

更新日: 2026-09-07

本書は、Desktop Companionの外界認識を「センサー機能の寄せ集め」ではなく、Desk Botが何を感じられるかという感覚器官として定義する正本である。

上位基準は `M5Stack Desktop Companion 設計思想 v0.1` および `PROJECT_LOCKS.md` とする。

## 1. 基本原則

センサーは、取得できる値の多さではなく、

**「この感覚を持つことで、この子は何を感じられるようになるのか」**

で採否と役割を決める。

感覚器官は、

**外界 → 感覚器官 → 感覚野 → 反射／Heart Engine／Pi5高次認知 → 行動**

の流れへ接続されなければならない。

生データを表示できるだけでは、感覚器官として完成とはみなさない。

## 2. M5Stack / Pi5の感覚系分担

### M5Stack

身体と常時稼働する低次感覚野を担当する。

Pi5が停止・切断していても、接触・接近・在席・環境変化・低次視覚等を感じ、最低限の反射とHeart Engineへの入力を継続できる構造とする。

### Raspberry Pi 5

高次感覚野・知覚統合・認知を担当する。

人物・物体・状況理解、会話文脈、記憶照合等、M5Stack単体では重い処理を担当する。

## 3. 購入済み・正式登録する感覚器官

### 3.1 M5Stack Unit ToF4M — U172

状態：**購入済み／採用検討対象として正式登録**

役割：**距離感覚・接近感覚**

主用途：

- Kimとの距離を測る
- 人や物体が近づいてきたことを知る
- 離れていったことを知る
- 接近速度・滞在距離の変化を将来的に感覚化する
- 視線・首・警戒・期待等の反射およびHeart Engine入力へ接続する

公式仕様上、VL53L1CX系ToFセンサーを用い、約4cm〜400cmを測距するI2Cセンサーである。

このセンサーの価値は単なる距離表示ではなく、

**「誰かが近づいてきた／そばにいる／離れていった」**

という空間的な感覚をDesk Botへ与えることにある。

### 3.2 M5Stack Unit TMOS PIR — U185

状態：**購入済み／採用検討対象として正式登録**

役割：**人の在席・存在・活動感覚**

主用途：

- 人がその場にいることを感じる
- 人の動作を感じる
- カメラだけに依存せず、人の存在を常時把握する
- 在席継続、離席、再来などをHeart Engine／生活リズムへ渡す
- 一人になった／誰かが戻った等の変化を自発行動の理由にする

公式仕様上、STHS34PF80を用いた高感度赤外線センサーで、人の在席および動作検知を目的とするI2Cユニットである。

通常の単純PIRよりも、熱放射による存在検知を扱える点を活かし、

**「動いたものを検出する」だけではなく「人がそこにいる」感覚**

として設計する。

### 3.3 M5Stack Unit ENV-Pro — U169

状態：**購入済み／採用検討対象として正式登録**

役割：**環境感覚**

主用途：

- 温度
- 湿度
- 気圧
- 将来的なVOC
- CO2相当値
- IAQ（室内空気質）

を環境状態として感じる。

公式仕様上、BME688を搭載し、温度・湿度・気圧に加えてVOC、CO2相当値、IAQ等の取得にも対応する。

Desk Botでは数値表示を目的とせず、例えば、

- 暑くなった
- 寒くなった
- 蒸してきた
- 空気が変わった
- 気圧が大きく変化した

などの**環境変化の感覚**へ変換し、Heart Engine・生活リズム・自発反応へ接続する。

閾値や感情への具体的影響量は、この段階では固定しない。

### 3.4 M5Stack Unit Hub — U006

状態：**購入済み／構成部品として正式登録**

役割：**感覚器官の接続基盤**

HY2.0-4P / Groveポートを1系統から3系統へ分岐し、U172、U185、U169を同時接続するために使用する。

公式仕様上、3つの拡張ポートは回路的に直結される。

したがって、Unit Hub自体は感覚器官ではなく、**複数の感覚器官をM5Stackへ接続する末梢神経の分岐部**として扱う。

## 4. 現時点の感覚構成

### 身体側・低次感覚

- M5カメラ：反射の目
- Unit ToF4M U172：距離・接近感覚
- Unit TMOS PIR U185：在席・存在・活動感覚
- Unit ENV-Pro U169：温湿度・気圧・空気環境感覚
- IMU：姿勢・揺れ・持ち上げ等の身体感覚
- タッチ：接触感覚
- マイク：低次聴覚／高次聴覚への入口
- 照度：明暗・昼夜等の環境感覚

### Pi5側・高次感覚

- Raspberry Pi Camera Module 3 Wide：理解する目
- 高次音声認識
- 人物・物体・状況認識
- 記憶との照合
- マルチモーダル認知

## 5. 重要な設計ルール

1. 各センサー値をHeart Engineへ直接垂れ流さない。
2. まず低次感覚野で、意味のある知覚状態・イベントへ変換する。
3. 即時性が必要なものはM5Stack側で反射可能にする。
4. 高次理解が必要なものだけPi5へ渡す。
5. Pi5切断時でも、M5Stack側の低次感覚と基本反応は生き続ける。
6. 複数センサーが同じ対象を観測しても、制御権を競合させない。
7. センサー間の相互補完を前提とする。例：TMOS PIRで在席、ToF4Mで距離、カメラで位置・人物情報を補完する。

## 6. 次に定義する内容

各感覚について、以下を一つずつ明文化する。

- 生データ
- M5側前処理
- 意味化された知覚イベント／状態
- 反射層へ渡す内容
- Heart Engineへ渡す意味
- Pi5へ渡す条件と内容
- Pi5から返る高次認知
- Pi5切断時のフォールバック
- 行動出力との接続

この洗い出しを完了してから、共通意味モデルと神経通信仕様を確定する。
