# M5Stack Desktop Companion 感覚器官聖典 v0.1

更新日: 2026-09-11

本書は、Desktop Companionの外界認識を「センサー機能の寄せ集め」ではなく、Desk Botが何を感じられるかという感覚器官として定義する正本である。

上位基準は `M5Stack Desktop Companion 設計思想 v0.1.md`、`M5Stack Desktop Companion 実装Step聖典 v0.3.md`、`PROJECT_LOCKS.md` とする。

## 1. 基本原則

センサーは取得値の多さではなく、

**「この感覚を持つことで、この子は何を感じられるようになるのか」**

で採否と役割を決める。

感覚器官は、

**外界 → 感覚器官 → Device Driver → Adapter / 感覚野 → Nerve Input → 反射／Heart Engine／Pi5高次認知 → 行動**

へ接続する。

生データを表示できるだけでは完成とみなさない。

## 2. 実装開始条件

外部感覚器官の統合は、CoreS3素体確認より先に行わない。

先にCoreS3公式環境だけで、DISPLAY、TOUCH、IMU、PROXIMITY、MIC、SPEAKER、CAMERA等の単独動作を確認する。

その後、Device Driver → Adapter → Nerve Inputの独自境界を作る。

## 3. M5Stack / Pi5の分担

### M5Stack

身体と常時稼働する低次感覚野を担当する。

Pi5停止時でも、接触・接近・在席・環境変化・低次視覚等を感じ、反射とHeart Engineへの入力を継続する。

### Raspberry Pi 5

高次感覚野・認知を担当する。

人物・物体・状況理解、会話文脈、記憶照合等の重い処理を扱う。

## 4. 購入済み・正式登録済み感覚器官

### M5Stack Unit ToF4M — U172

状態：**購入済み**

役割：**距離感覚・接近感覚**

距離値そのものを人格へ渡さず、近づいた／近くにいる／離れた等の共通意味へ変換する。

最初の外部感覚縦貫通対象とする。ただしCoreS3素体確認完了後に開始する。

### M5Stack Unit TMOS PIR — U185

状態：**購入済み**

役割：**人の在席・存在・活動感覚**

カメラだけに依存せず、人がその場にいること、活動していることを低次感覚として扱う。

### M5Stack ENV-Pro — U169

状態：**購入済み**

役割：**環境感覚**

温度・湿度・気圧を基本とし、環境変化を意味化してHeart Engineや生活リズムへ接続する。

VOC、CO2相当値、IAQ等は将来利用候補として保持する。

### M5Stack Unit Hub — U006

状態：**購入済み**

役割：**接続基盤**

U172、U185、U169を同時接続するためのHY2.0-4P/Grove 1→3分岐。感覚器官ではなく末梢神経の分岐部として扱う。

### Raspberry Pi Camera Module 3 Wide

状態：**購入・採用LOCK済み**

役割：**Pi5側の理解する目**

M5Stack側カメラは反射の目、Pi5側カメラは高次認知の目とする。

## 5. 現時点の感覚構成

### M5Stack側・低次感覚

- M5カメラ：反射の目
- Unit ToF4M U172：距離・接近
- Unit TMOS PIR U185：在席・存在・活動
- Unit ENV-Pro U169：温湿度・気圧・環境変化
- IMU：姿勢・揺れ・持ち上げ
- タッチ：接触
- マイク：低次聴覚／高次聴覚への入口
- 照度：明暗・昼夜

### Pi5側・高次感覚

- Raspberry Pi Camera Module 3 Wide：理解する目
- 高次音声認識
- 人物・物体・状況認識
- 記憶照合
- マルチモーダル認知

## 6. 重要な設計ルール

1. 製品固有値をHeart Engineへ直接流さない。
2. Device Driverでハード差を扱う。
3. Adapterで製品差を吸収し、意味化・正規化する。
4. 神経へは製品非依存のNerve Inputを渡す。
5. 即時性が必要なものはM5Stack側で反射可能にする。
6. 高次理解が必要なものだけPi5へ渡す。
7. Pi5切断時でもM5Stack側の低次感覚と基本反応を継続する。
8. 複数センサーが同じ対象を見ても、身体制御権を直接競合させない。

## 7. 感覚の実装順

CoreS3素体確認後、基本順を、

**ToF4M → TMOS PIR → ENV-Pro → 視覚 → タッチ → IMU → 聴覚 → その他感覚**

とする。

各感覚について、

- 生データ
- Device Driver
- Adapter
- 意味化されたNerve Input
- 反射への意味
- Heart Engineへの意味
- Pi5へ渡す条件
- Pi5切断時フォールバック
- 行動出力
- ログ・実機確認条件

を定義する。

## 8. OSSの扱い

先行OSSやGitHub実装は、ゼロベース基盤と独自層が成立した後に参考候補として調査してよい。

初期基盤へ組み込まない。親Repoにしない。旧OSSの都合で感覚系設計を変更しない。

必要機能を採用する場合は現行アーキテクチャへ適合させて再評価・再実装する。
