# M5Stack Desktop Companion — 感覚野・脳機能配置 正式設計

更新日: 2026-09-07

## 0. この文書の位置づけ

この文書は、

- `M5Stack Desktop Companion 設計思想 v0.1`
- `M5Stack Desktop Companion 実装Step聖典 v0.3`
- `PROJECT_LOCKS.md`

を前提に、Desk Botの感覚器官・感覚野・反射・Heart Engine・Pi5側高次認知の役割分担を明文化する正本である。

最上位ゴールは変えない。

**机の上に常にいて、周囲を感じ、反応し、気分が変わり、少しずつ関係性が育つ相棒**

として成立させる。

---

## 1. 上位原則

### 1-1. M5Stackは身体と低次脳を持つ

M5Stackは単なるセンサー端末や表示端末にしない。

M5Stack側に、少なくとも以下を残す。

- 感覚器官の常時監視
- 低次感覚処理
- 反射
- Heart Engine
- 基本的な自発行動
- 表情
- 視線
- 首
- 基本的な生活リズム

Pi5が停止しても、M5Stack側だけで「生きている感じ」を維持する。

### 1-2. Pi5は高次認知を担当する

Pi5は、M5Stackだけでは重い、または意味理解が必要な処理を担当する。

- 高度画像認識
- 人物同定
- 状況理解
- ASR
- LLM
- TTS
- 長期記憶
- 高次認知
- 複数感覚と過去記憶を使った意味判断

### 1-3. 低次感覚野と高次感覚野を分ける

各感覚について、M5Stack側の軽量処理とPi5側の高次処理を分ける。

M5Stackで十分に判断できる内容はPi5へ依存しない。

意味理解が必要な場合のみPi5側へ上げる。

---

## 2. 視覚野

### 感覚器官

- M5Stack内蔵カメラ

### M5Stack側：低次視覚野

常時・軽量で扱う。

候補：

- 顔がいる／いない
- 顔や人の位置
- 動きの有無
- 大きな動き
- 近づいた／離れたの粗い変化
- 手振り等の単純ジェスチャー
- 視線・首を向けるためのターゲット位置

M5Stack側だけで成立させる反応例：

- 人が来た → 見る
- 顔位置が変わった → 視線を追従
- 手を振られた → 反応する

### Pi5側：高次視覚野

必要時のみ扱う。

候補：

- 誰なのか
- Kimかどうか
- 何を持っているか
- 何をしているか
- 机上の物体や状況の意味
- 複数物体・複数人物の関係
- 過去記憶との照合

### 原則

**M5で見て、M5で足りる認識はM5で終える。**

より深い意味理解が必要な場合のみ、必要な画像または切り出しデータをPi5へ送る。

---

## 3. 聴覚野

### 感覚器官

- M5Stack内蔵マイク

### M5Stack側：低次聴覚野

- 音がした／していない
- 大きな音
- 音声区間の検出
- 必要に応じて音方向の粗い推定
- 呼びかけ開始のきっかけ

反射例：

- 大きな音 → 一瞬驚く
- 音方向が分かる → そちらを見る

### Pi5側：高次聴覚野

- ASR
- 話者識別
- 発話内容の理解
- 文脈理解
- LLMとの会話
- TTS生成

---

## 4. 体性感覚野

### 感覚器官

- 接触センサー
- IMU
- 距離センサー
- 将来の圧力センサー等

### M5Stack側で扱う

- 触られた
- 接触継続時間
- 揺らされた
- 持ち上げられた
- 傾けられた
- 近づいた／離れた
- 強い接触
- 必要に応じて「撫でられた」等の複合判定

これらは生命感に直結するため、基本的にPi5を待たずM5Stack側で即時反応する。

例：

- 急に触られる → 一瞬目を開く
- 撫でられる → 目を柔らかくする
- 持ち上げられる → 驚く
- 顔や手が近づく → 視線を向ける

---

## 5. 環境感覚野

### 感覚器官

購入済み：

- 温度
- 湿度
- 距離
- 接触

既存／利用候補：

- 照度

### M5Stack側で扱う

環境感覚は基本的にM5Stack側で常時監視する。

候補：

- 明るい／暗い
- 暑い／寒い
- 湿度が高い／低い
- 周囲に人や物が近い／遠い

これらはHeart Engineや生活リズムに直接つなぐ。

例：

- 暗くなる → 動きを静かにする
- 夜＋暗い＋静か → sleepiness上昇
- 長時間近くに人がいない → boredom上昇

高度な意味判断が必要な場合のみPi5へ渡す。

---

## 6. Heart Engineとの関係

Heart EngineはM5Stack側に置く。

理由：

Pi5停止やLAN断でも、

- 機嫌
- 親密度
- 好奇心
- 退屈
- 眠気
- attention

などの心の状態を維持するため。

各感覚野の低次認識結果は、反射とHeart Engineの両方へ渡せる構造にする。

例：

接触
→ 反射：すぐ目を細める
→ Heart Engine：mood + / affection +

## 8. 神経言語との関係

この配置を前提に、神経系は2層で考える。

### 共通化するもの

- 意味モデル
- 語彙
- ID
- payload定義

### 分けるもの

- M5Stack内部の軽量な内部イベント／API
- M5Stack ↔ Pi5間の通信・シリアライズ・再接続等

原則：

**語彙は共通、文法と輸送手段は別。**

神経プロトコルの具体仕様は、本書で定義した各感覚野・高次認知・Heart Engine・身体出力の配置を基準に決定する。

## 10. 現在の結論

Desk Botの感覚系は、

**感覚器官 → M5Stack低次感覚野 → 必要に応じてPi5高次感覚野 → 反射／Heart Engine／記憶／行動 → 身体**

という分散構造を正式採用する。

M5Stackは単なる端末ではなく、身体と低次脳を持つ。

Pi5は高次認知を担う。

これにより、Pi5が停止しても「そこにいる感じ」を失わず、Pi5接続時には高度な認知能力を得られる構造とする。
