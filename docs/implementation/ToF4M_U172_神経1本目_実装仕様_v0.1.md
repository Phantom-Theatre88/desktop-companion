# ToF4M U172｜神経1本目 実装仕様 v0.1

更新日: 2026-09-11

## 現在の位置づけ

**DEFERRED / 設計仕様として保持**

本書はToF4M U172を最初の外部感覚として縦貫通させるための仕様である。

ただし、2026-09-11のゼロベース方針により、**今すぐ実装する仕様ではない**。

先に、

1. CoreS3 + Arduino + M5Unified + M5GFXの新規プロジェクト作成
2. CoreS3公式APIだけで素体確認
3. Hardware / Device Driver層の成立
4. Adapter層の成立
5. Nerve Input境界の成立

を完了する。

旧Yuki／StackChan／ESP-IDF 5.5.4上に作成されたToF4MコードはLEGACY参考資産とし、現行実装へそのまま継承しない。

## 小ゴール

ToF4M U172の製品固有距離値から意味化された近接情報を作り、NeuronとSynapseを通して上位層へ配送できる「神経1本目」の最小骨格を成立させる。

ToF単独で人物を断定しない。

`PERSON_APPROACHING` はTMOS・Vision等とのPerception Integration後に生成する意味とし、ToF単独では `PROXIMITY_*` を出力する。

## 1. 何を感じる感覚か

距離そのものではなく、対象が近づいた／近くにいる／離れたという近接変化を感じる。

## 2. 生データ

U172から取得する距離値。

製品固有I2C・センサー仕様はDevice Driver層だけが知る。

## 3. 前処理

```text
U172
↓
Device Driver
↓
Raw distance
↓
Adapter / Perception
↓
Nerve Input
```

Adapterが前回値・状態・有効性を見て製品非依存の意味へ変換する。

## 4. timestamp / confidence

取得側または知覚統合側で `timestamp_ms` と `confidence` を付与する。

confidence算出方式は実機評価前に固定しない。

## 5. 意味化イベント／状態

初期候補：

- `PROXIMITY_APPROACHING`
- `PROXIMITY_NEAR`
- `PROXIMITY_LEAVE`

正式なコード表現は新基盤実装時に現行Nerve Input定義へ合わせる。

## 6. 反射層

Synapseにより近接意味をReflexへ配送する。

Eyes / Neck等の具体動作は、Behavior Selectorと身体出力層が成立してから接続する。

## 7. Heart Engine

同じ意味イベントをHeart側へ配送可能にする。

Heart数値仕様が未決のため、係数はこの文書でLOCKしない。

## 8. Pi5

人物識別等の高次認知が必要な場合だけ、共通意味としてPi5へ渡す。

Pi5停止時でもToF感覚・意味化・M5側反射を継続できる構造とする。

## 9. Behavior Selector

神経回路が身体を直接占有しない。

反射・Heart等からの行動要求をBehavior Selectorへ渡し、競合する身体出力だけを仲裁する。

## 10. ログと実機確認条件

最低限、

`raw distance → PROXIMITY event → Synapse delivery → Reflex/Heart request → Behavior Selector → Body Output`

の因果を追えることを完成条件とする。

## 11. 閾値

旧実装で使った、

- near: 600 mm
- leave: 750 mm
- approaching delta: 80 mm / sample

は**正式LOCK値ではないLEGACY参考値**とする。

新基盤でサンプリング周期、ノイズ、机上距離を実測してから決定する。

## 12. 現在のブロッカー

旧文書にあった「Yuki本体がESP-IDF 5.5.4なのでU172をESP-IDFへ適合させる必要がある」というブロッカーは**失効**した。

現行方針ではArduino + M5Unifiedを初期基盤とし、まずCoreS3公式環境で正常性を確認する。

ToF4M実装方式は、その時点の新基盤に合わせて改めて決定する。
