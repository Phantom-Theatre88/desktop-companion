# M5Stack Desktop Companion
## 演技モーション設計 聖典 v0.2

**Status: LOCK 🔐**  
**対象:** 2軸M5Stack本体における「首＋目＋画面描写＋イベント」の総合演技設計  
**位置づけ:** v0.1の演技設計を、100演技案および既存ロボット表現ライブラリの照合結果を踏まえて整理・精度向上した正本。

---

# 1. v0.2での更新点

v0.1では「首モーション」から「演技モーション」へ設計思想を拡張した。

v0.2ではさらに、以下を整理した。

1. 100演技案を土台に、重複・複合・イベント依存を分離。
2. 既存ロボット表現ライブラリで頻出する対人ニュアンスを追加。
3. 感情そのものと、感情を補助する動き・エフェクトを分離。
4. 天気・日付・誕生日等は「基本演技」ではなくイベント組み合わせへ移動。
5. 固定アニメーション100本ではなく、少数の共通パラメータから多様な演技を生成する方針を明確化。

# 2. 基本原則

## 2.1 現行ハードウェア制約

現行M5Stackの首は2軸とする。

- Yaw：左右
- Pitch：上下

Roll（左右への物理的な首かしげ）は前提にしない。

Roll的な印象が必要な場合は、以下を複合する。

- 目の左右差
- 顔全体の画面位置
- 顔全体の拡大縮小
- 視線
- 目の傾き
- Yaw / Pitch
- タイミング差

---

## 2.2 演技は4レイヤーで構成する

1. **首**
2. **目**
3. **画面描写**
4. **イベント演出**

重要なのは「首が動くこと」ではなく、ユーザーから見て意味が読めること。

# 4. イベント依存演技は基本演技から分離する

以下は独立した基本演技として固定せず、**基本演技＋イベント**として構成する。

例：

- 晴れを喜ぶ = D01/D06 + 天気D01
- 雨を眺める = A04/B05 + 天気D04
- 雷に驚く = F01/F02 + 天気D05
- 雪に興味を示す = B11/D07 + 天気D06
- 誕生日を祝う = D02 + カレンダーC12
- 記念日を喜ぶ = D01/D08 + カレンダーC13
- ハロウィンを楽しむ = D17 + カレンダーC09

これにより、天気・日付イベントの増加が基本演技辞書の肥大化につながらない。

# 6. 実装単位

演技は固定動画として保存しない。

各演技は次のパラメータセットとして表現する。

```text
ActingMotion {
  neck:
    yaw
    pitch
    speed
    easing
    hold
    return_speed

  eyes:
    expression_id
    gaze_x
    gaze_y
    asymmetry
    blink
    color
    glow

  screen:
    face_x
    face_y
    scale
    shake
    overshoot
    fade

  event:
    event_id
    position
    duration

  effects:
    fx_ids[]

  timing:
    attack
    hold
    release
}
```

# 7. v0.2の考え方

## 7.1 100演技はゴールではなく土台

100演技案は表現を広く洗い出すための有効な母集団として扱う。

v0.2では、それをそのまま100本固定するのではなく、

- 基本演技
- イベント複合
- 演技エフェクト

へ分けた。

## 7.2 対人ニュアンスを重視する

既存ロボット表現で頻出する、以下のニュアンスを明示的に採用する。

- 謝る
- 気まずく笑う
- 強く照れる
- 悪戯っぽい
- 得意げ
- 見惚れる
- 「あっ」と気づく
- ウインク
- 涙
- 疲れ切る
- 小さく笑う

これらは、机上の相棒としての関係性表現を豊かにする。

# 8. 参考にした外部設計思想

v0.2の精査では、以下の既存ロボット表現ライブラリ／設計思想を照合対象とした。

- Kaia Face系：対人ニュアンスの多い表情語彙
- RoboEyes系：視線・瞬き・curiosity・sweat・confused・laugh等の再利用可能な演技要素
- Procedural Expression Library系：固定画像ではなく、パラメータ・補間によって表情遷移を生成する考え方

外部ライブラリをそのままコピーするのではなく、M5Stack Desktop Companionの上位思想に合わせて再編成する。

# 9. LOCK事項 🔐

以下を正式LOCKする。

1. 現行M5Stackは2軸首（Yaw＋Pitch）前提とする。
2. Rollを前提としたハード設計にはしない。
3. 演技は **首＋目＋画面描写＋イベント** の4レイヤーで構成する。
4. 100演技案は母集団として保持するが、100本の固定動画にはしない。
5. 基本演技・イベント複合・演技エフェクトを分離する。
6. 天気・日付・誕生日等はイベントとの組み合わせで表現する。
7. 対人ニュアンスとして、謝る・照れる・気まずい・悪戯・得意げ・見惚れる・気づく・ウインク・涙・疲労・小笑いを正式採用する。
8. 表情と動きは固定画像ではなく、可能な限りパラメータ駆動・補間で生成する。
9. 演技の意味の読み取りやすさを、物理動作の忠実さより優先する。
10. 「何もしない」「静止する」「微細に生きている」も正式な演技として扱う。
11. 今後はこのv0.2を正本とし、v0.1は設計過程の記録として残す。
