# M5Stack Desktop Companion
## イベント演出パーツ設計 聖典 v0.1

**Status: LOCK 🔐**  
**位置づけ:** M5Stack Desktop Companion の「存在感」を高めるためのイベント演出レイヤー設計。  
**基準:** 目の表情20種LOCK版を主役とし、イベント演出はその意味を補強する補助レイヤーとして扱う。

---

## 1. 基本思想

イベント演出は、単なる絵文字や静止アイコンの表示ではなく、  
**「短いアニメーションによる小さな演技」** として扱う。

主役は常に「目の表情」であり、イベントパーツは補助表現とする。

### 表現レイヤー

1. **目の表情**
   - 形
   - 色
   - Glow / Bloom
   - まぶた
   - 視線
   - 左右差
   - 瞬き

2. **首・身体モーション**
   - 傾き
   - うなずき
   - 引く
   - のぞき込む
   - 揺れ
   - 眠気による落ち込み

3. **イベント演出**
   - 感情
   - 状態
   - カレンダー
   - 天気

イベント演出は、目と首の演技を邪魔せず、必要な時だけ短時間表示する。

# 2. イベント分類

イベントパーツは以下の4カテゴリに分ける。

- **A. 感情イベント**
- **B. 状態イベント**
- **C. カレンダーイベント**
- **D. 天気イベント**

# 6. D：天気イベント

| D03 | 雲 | 曇り | ゆっくり漂う |
| D04 | 雨 | 雨 | 小さな雨粒が数滴落ちる |

| D06 | 雪 | 雪 | 雪粒がゆっくり落ちる |
| D07 | 霧 | 霧 | 薄いもやが横切る |

### 将来連動

天気情報  
→ 内部状態へ小さな影響  
→ 目の表情  
→ 首モーション  
→ 天気イベント

という流れを目標とする。

例：

- 雨 → 少し落ち着いた／憂鬱な目 + 雨演出
- 快晴 → 明るい目 + 太陽
- 雷 → 警戒目 + 首が引く + 雷
- 雪 → 好奇心の目 + 雪粒

# 7. アニメーション共通ルール

イベント演出は基本的に以下の3段階を持つ。

**出現 → 演技 → 消失**

### ルール

- 常時表示しない
- 必要時だけ短時間表示
- 目の表情を隠さない
- 目より目立ちすぎない
- 画面端・目の横・頭上相当位置を中心に使う
- 1イベントで過剰な動きをさせない
- 短く、意味が読み取れる動きにする
- 状態によっては周期反復を許可する
- 同時表示数には上限を設ける

---

# 8. 表示位置の候補

イベントパーツは固定位置ではなく、意味によって配置を変える。

- 目の左上
- 目の右上
- 片目の横
- 画面中央上部
- 下部
- 目の間
- 画面外へ抜ける軌道

例：

- ハート → 目の横から上へ
- Zzz → 上方向へ漂う
- 汗 → 片目横から下へ
- ひらめき → 上部に一瞬
- 雨・雪 → 画面全体へ薄く
- 本・コーヒー → 下部寄り

# 9. 実装思想

イベントを固定アニメーション動画として大量に持つのではなく、  
可能な限り以下をパラメータ化する。

- 位置
- 大きさ
- 回転
- 透明度
- 発光
- 色
- 移動速度
- 表示時間
- 繰り返し回数
- 出現方法
- 消失方法
- 揺れ
- 軌道
- 粒子数

これにより、同じイベントでも微妙に異なる演技を作れる。

# 10. Heart Engineとの将来連携

イベントはランダムに出すものではなく、  
**内部状態または外部イベントに理由がある時に出す。**

例：

- 触られる → 愛着上昇 → A01 ハート
- 顔を発見 → 好奇心上昇 → A02 キラキラ
- 長時間反応なし → 退屈 → B09 もや
- 眠気上昇 → B01 → B02へ遷移
- バッテリー低下 → B07
- 日付一致 → C系
- 天気取得 → D系
- センサー異常 → B10

# 11. LOCK事項

以下を正式LOCKする。🔐

1. イベント表現は**静止絵文字ではなく短いアニメーション演出**とする。
2. イベントは **感情 / 状態 / カレンダー / 天気** の4カテゴリで管理する。
3. イベントは目の表情を補助するレイヤーであり、主役は目とする。
4. 基本構成は **出現 → 演技 → 消失**。
5. イベントを常時出しっぱなしにしない。
6. 睡眠系は **眠気途中** と **睡眠中** を分ける。
7. カレンダー連動・天気連動を将来実装対象とする。
8. 天気や日付は単なる情報表示ではなく、内部状態・目・首の演技との連動を目指す。
9. 大量の固定動画ではなく、可能な限りパラメータ駆動で実装する。
10. 今後のイベント追加は、この設計思想を壊さない範囲で拡張する。
