# 1. この設計に至った経緯

当初は「首モーション一覧」を作り、M5Stackの首動作だけで感情表現を整理する方針だった。

しかし、M5Stackの首は基本的に2軸であり、物理的に扱えるのは以下の2方向に限られる。

- **Yaw：左右を向く**
- **Pitch：上下を向く**

そのため、人間や3軸ロボットのような **Roll＝左右への首かしげ** は物理的にはできない。

さらに検討を進めると、「のぞき込む」「引く」「照れる」「しょんぼりする」「迷う」といった演技は、首の2軸だけでは十分に表現できないことが明確になった。

特に、

- のぞき込む
- 引く
- ためらう
- 照れる
- 驚く
- しょんぼりする

といった表現は、首の角度だけではなく、**目の形・視線・画面内の顔位置・拡大縮小・揺れ・イベント記号**などを組み合わせることで成立する。

このため、「首モーション一覧」から一段広い考え方へ切り替え、

> **首の動きではなく、ロボット全体の“演技モーション”として設計する**

ことを正式方針とする。

---

# 2. 基本原則

## 2.1 2軸首を前提にする

現行M5Stackでは、首の物理表現はYaw＋Pitchを前提とする。

3軸化は将来のハードウェア拡張候補ではあるが、現在の設計を3軸前提にはしない。

---

## 2.2 演技は複数レイヤーの合成で作る

演技は次の4レイヤーを組み合わせて作る。

1. **首の動き**
2. **目の表情**
3. **画面描写**
4. **イベント演出**

単一レイヤーだけで表情を完成させない。

---

# 3. 演技を構成する4レイヤー

## Layer 1：首の動き

物理サーボで表現する。

主な要素：

- Yaw
- Pitch
- 動作速度
- 加速度
- 停止時間
- 戻り速度
- 繰り返し回数
- 動き始めのタイミング
- 目との先行／遅延関係

例：

- 左右を見る
- 上下を見る
- うなずく
- 首を振る
- 素早く振り向く
- ゆっくり沈む
- 眠気でカクンと落ちる

---

## Layer 2：目の表情

すでにLOCKした20種類の目表現を基準とする。

主な要素：

- 目の幅
- 目の高さ
- 傾き
- まぶた
- 左右差
- 視線
- 瞬き
- 色
- Glow / Bloom
- エッジの柔らかさ

Rollが使えない分、左右差や視線方向によって「首をかしげたような印象」を補助することもできる。

ただし、左右差だけに頼らず、画面描写も含めて演技を構成する。

---

## Layer 3：画面描写

ディスプレイ内で顔全体を動かし、物理首だけでは作れない奥行き感や距離感を補う。

主な候補：

- 顔全体のX位置
- 顔全体のY位置
- 顔全体の拡大
- 顔全体の縮小
- 画面内で沈む
- 画面内で浮く
- 一瞬の揺れ
- 微振動
- オーバーシュート
- 余白の増減
- 視線中心位置の移動
- 必要に応じた画面全体の短い動き

### 重要

「のぞき込む」「引く」などの演技は、物理的な前後移動ではなく、**画面内の顔スケールや位置変化を使って疑似的に表現する**。

例：

### のぞき込む

- 首：対象方向へYaw/Pitch
- 目：少し大きく、対象へ視線
- 画面：顔全体を少し拡大
- 必要なら顔位置をわずかに前へ寄せた印象にする

### 引く

- 首：少し上または反対方向へ逃がす
- 目：驚き／警戒系
- 画面：顔全体を少し縮小
- 一瞬の後退感を出す

---

## Layer 4：イベント演出

イベント演出パーツ設計 聖典 v0.1 を使用する。

カテゴリ：

- 感情イベント
- 状態イベント
- カレンダーイベント
- 天気イベント

例：

- ハート
- キラキラ
- はてな
- 汗
- Zzz
- 本
- コーヒー
- 雨
- 雪
- 桜
- クリスマス

イベントは主役ではなく、目・首・画面演技を補強する。

# 7. 現時点では数値を決めない

この段階では、サーボ角度や速度などの具体数値はLOCKしない。

先に行うことは、

1. どんな演技が必要かを洗い出す
2. 重複を整理する
3. 目・首・画面・イベントの役割を分ける
4. その後に数値パラメーターを振る

という順番とする。

数値を先に決めると、似た動きばかりになる危険があるため、**演技設計を先、パラメーター設計を後**とする。

---

# 8. 重要な考え方

## 「首が動く」のではなく「ロボットが演技する」

最終的なゴールはサーボを動かすことではない。

ユーザーから見て、

- 気になった
- 驚いた
- 嬉しい
- 眠い
- こちらを見ている
- 少し距離を取った
- 興味を持って近づいた

と自然に感じられることが重要である。

物理的にできない動きは、画面描写や目の演技で補う。

これは「AIを喋らせるのではなく、存在させる」というM5Stack Desktop Companionの上位設計思想に従う。

---

# 9. 半LOCK事項 🔐

以下を半LOCKする。

1. 現行M5Stackは**2軸首（Yaw＋Pitch）前提**で設計する。
2. Rollを前提とした演技設計はしない。
3. 「首モーション一覧」単独ではなく、**演技モーション一覧**として設計する。
4. 演技は **首＋目＋画面描写＋イベント** の4レイヤーで構成する。
5. 「のぞき込む」「引く」などは首だけで再現せず、画面内の拡大縮小・位置変化なども利用する。
6. 目の左右差は補助手段の一つであり、表現全体を左右差だけに依存させない。
7. まず演技の種類を洗い出し、その後に数値パラメーターを与える。
8. 物理的な動作の再現性よりも、ユーザーから見た**意味の読み取りやすさ**を優先する。
9. 「何もせず静止する」ことも有効な演技として扱う。
10. このv0.1は演技一覧の洗い出しを進めるための基準文書とする。
